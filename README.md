# Screener_backend

## Требования

- Docker с поддержкой Linux-контейнеров
- Docker Compose v2
- Make

Go для запуска через Docker устанавливать не требуется.

## Запуск

Скопируйте пример настроек:

```bash
cp .env.example .env
```

Запустите окружение:

```bash
make up
```
Команда `make up` собирает образы, запускает PostgreSQL и ждёт её готовности.
Затем сервис `migrate` применяет ожидающие SQL-миграции. Приложение запускается
только после успешного завершения `migrate`.

При ошибке миграции `make up` завершается с ошибкой. Посмотреть причину можно
командой `docker compose logs migrate`.

Проверить состояние контейнеров:

```bash
docker compose ps
```

Приложение доступно по адресу [http://localhost:8080/api/v1/](http://localhost:8080/api/v1/).
Ожидаемый ответ:

```json
{"status":"ok"}
```

## Настройки

Настройки задаются в `.env`. Пример находится в `.env.example`.
Файл `.env` не добавляется в Git.

`DATABASE_URL` формируется Docker Compose из настроек `POSTGRES_USER`,
`POSTGRES_PASSWORD` и `POSTGRES_DB`. Они определены выше строки подключения
в файле настроек. Для значений со специальными символами URL может потребоваться
URL-кодирование при составлении строки подключения.

PostgreSQL доступен приложению по адресу `postgres:5432`, а с компьютера —
по адресу `localhost:${POSTGRES_PORT}`. `POSTGRES_PORT` задаёт порт компьютера;
порт PostgreSQL внутри контейнера остаётся `5432`.

## Миграции

Схема PostgreSQL изменяется через версионируемые SQL-файлы в `migrations/`.
Каждый файл содержит секции `-- +goose Up` для применения и `-- +goose Down`
для отката. Первая миграция создаёт пустую служебную схему `migration_probe`
для проверки механизма. Доменные таблицы будут описаны отдельно в ER-модели
(ТЗ, приложение B).

| Команда | Действие |
| --- | --- |
| `make migrate-up` | Применить ожидающие миграции |
| `make migrate-down` | Откатить последнюю применённую миграцию |
| `make migrate-status` | Показать статус миграций |
| `make migrate-create name=add_example` | Создать версионируемый SQL-файл с секциями Up и Down |
| `make test-migrations` | Проверить цикл up → down → up на отдельной чистой PostgreSQL |

Повторный запуск `make migrate-up` при отсутствии новых миграций оставляет
схему базы и историю миграций без изменений.

## Остановка

```bash
make down
```

Данные PostgreSQL сохраняются в named volume и доступны после повторного `make up`.

## Просмотр логов

```bash
docker compose logs -f app
docker compose logs -f postgres
```

Для выхода из просмотра логов нажмите Ctrl+C.
